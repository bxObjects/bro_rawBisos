* Stage 1: Establish the CBM Tree with Airflow as First webHere-Collective Capability

Goal: Build the walkable CBM tree structure under
=bro_rawBisosPlatform/sys/cbm/= and plant airflow as its first
capability. Depends on the =bisos.capability= Stage 1 work
(=cbmProc-seed.cs= + =cbmProc.spcs= template must exist and be
=pip install -e='d).

The tree becomes the concrete demonstration of the CBM pattern ---
airflow as one *webHere-collective* capability with all four systemd
units (db, webserver, scheduler, triggerer) materialized in one shot
from a single =cbmProc.spcs=. Tree layering follows the platform
README: =sys/cbm/<realm>/<capabilityType>/<capabilityName>/= where
realm = =collective= and capabilityType = =webHere= for airflow.

** Design Decisions Captured Before Stage 1 Begins

1. *Uniform leaf filename is =cbmProc.spcs=* (from
   =bisos.capability= Stage 1). One per capability. Which capability
   it represents is declared inside via
   =cbmProc_seedInfo.setup(capabilityName="airflow")=.

2. *Directory-per-capability layout at leaf level.* Since the
   filename is fixed (=cbmProc.spcs=), each capability needs its own
   directory to hold its =cbmProc.spcs= + sibling =cbmProc.control=
   + =cbmProc.status=.

3. *=ftoBranchProc.spcs= placement is flexible ---
   "at least one under collective".* One is enough to prove the
   walker; more can be added later. Not the design pivot; just
   exercises the tree-walking capability that's already tested.

4. *Airflow's =cbmProc.spcs= is a POINTER, not an inliner (PIVOTED).*
   Original decision (as recorded here) was to inline the CBS content
   (=cba_seed.setup(...)= + =cba_sysd_seed.setup(sysdUnitsList=[...])=)
   into the =cbmProc.spcs=. During implementation this was pivoted
   in =bisos.capability='s Stage 2: the =.spcs= is now a ~10-line
   pointer file (=capabilityName= + =cbsSpec=), and CBM subprocess-
   invokes the CBS at =cbm_materialize= time. Load-bearing principle:
   *CBM sits on top of CBS; does not duplicate CBS content.* The
   airflow-cbs.pcs at =/bisos/asc/web/bin/= is unchanged and pointed
   to via =cbsSpec="airflow-cbs.pcs"= (basename form).

5. *Initial =cbmProc.control= = =available=.* Not =enabled=. First
   walk after planting is a no-op --- user must explicitly run
   =cbm_enable= before =cbm_materialize= will do anything. Safe
   default; nothing gets materialized by accident.

6. *We're in a container --- no actual materialization here.* The
   VM is where materialization actually runs. This stage builds the
   tree structure and verifies the walker + control-gate wiring;
   materialization outcomes are exercised on a VM.
