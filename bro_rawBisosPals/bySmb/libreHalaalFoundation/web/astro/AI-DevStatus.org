* Key Design Decisions
  - PALS-BXO declares, platform holds state (user's model, refined, 2026-10-19; WorkPlan 2.5):
    =/bisos/platform/sys/pals/<palsBxo>/= (path, origin), =<palsBxo>/sys/cbm/<cbm>/= (capabilityType,
    relative cbsSpec), leaves at =sys/cbm/pals/<palsBxo>/<cbm>/= (user chose this over
    =pals/<type>/<cbm>/=). FileParams throughout.
  - .here names (WorkPlan 2.1): host-local =/bisos/var/palsHere/uri.list=, 127.0.55.x assigned once and
    stored, never reused (retire by commenting out), provenance per line; =palsHereIpOf()= for vhosts.
    dnsCap creates the palsHere dblock (=hostsDblockCommands=), not a pals-side step.
  - Spread-planted files (=.spcs=, WorkPlan 2.2): one generic file per role in bisos.pals, symlinked into
    each PALS's cbm/; the PALS is the nearest directory up with =uri/here/value=; paths never resolved.
  - Banner as LaTeX (user): Comic Sans MS is not free, Comic Neue + FakeBold=2.2 is the nearest; renamed
    =lhfBanner.jpg= so browsers do not keep the cached FPF image under the old URL.
  - Superseded and moved out (kept in the session scratchpad only): the astroPoc's =content/bin=
    scripts (=lcntBodies.py=, =filesNodes.py=, =hva/=) --- bisos.webCap's contentTree_csu does that work.
  - Negative results:
    - A leaf followed the CBS symlink (=resolveCbsSpec= used =Path.resolve=), so =pals-cbs.spcs= ran
      as the generic file and found no PALS. Fixed in bisos.capability (=.absolute()=). Those failed runs
      still logged "ran: cbs_materialize ok" in the leaf's cbmProc.status (PyCS exits 0 on failure);
      the two lines (01:26, 01:27 on 2026-10-19) are left in place.
    - dnsCap's ensure and update backups in the same second had one name; the original /etc/hosts was
      overwritten once (=/etc/hosts.20261018231503= is NOT the original). Fixed (=.preEnsure=).
    - The first request right after an nginx reload got the default page: reloads are asynchronous.
    - =palsForEtcHosts= must set no opResults: the framework prints them into the dblock.
