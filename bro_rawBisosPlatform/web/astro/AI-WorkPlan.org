* Stage 3: From Gatsby to Astro, With a Content Tree

<<Stage 3>>

Goal: replace Gatsby with Astro as the engine of BISOS static sites, and make a site's pages come from
a content tree on the file system, =content/tree/=, in the model of the ByStar Plone 3 ContentTree.

Decided 2026-10-17 (user): Gatsby is in maintenance mode, and our investment in it is small. The
content is LaTeX processed by HeVeA (already HTML, not MDX); LCNT documents carry their metadata
as file parameters; the same LaTeX model produces Reveal presentations. All ByStar Plone 3 sites
were built from a =ContentTree/= on disk; some are multilingual (Farsi, French), and RTL is a
requirement. Astro over Docusaurus: Astro takes HeVeA's HTML as it is (Docusaurus's MDX rejects
raw HTML) and its build can read the parameter files directly. A proof of concept first; replacing
Gatsby is the immediate focus; reproducing freeprotocols.intra in a PALS is deferred.

The legacy model (=/bxRepos/mb-ephemera/pub-shuttle/lcaPlone3=, the FPF site): =ContentTree/= is a
BISOS walkable tree (=_tree_= node/leaf, =_treeProc_=); a node's =objectType= is =folder=, =page=,
=pageLcnt= (body built from an LCNT document by HeVeA), =files= or =custom= (=lcntLists=); its
parameters are one file each (=folderTitle=, =pageTitle=, =pageDescription=, =pubState=,
=excludeFromNav=, =layoutLeftPortlets=, ...); a page's body is =contentBody.html=; the left
navigation order is =nodesOrdered= / =leavesOrdered=. The old slider (=homeSlider=) is ignored;
Reveal will replace it.
